# OpenPLi compatibility review — 2 November 2026

Scope: the three maintained Python 3 packages FullHDGlass, PiconHub and GSU. Official OpenPLi Enigma2 release-9.2 and develop were checked at the exact revisions in `openpli-review-20261102.json`. This is source/native-component validation, not receiver acceptance. OpenPLi 8.x/Python 2 is outside this review.

## Results

| Package | Checked source files / imports / direct calls | Result |
| --- | --- | --- |
| FullHDGlass | 124 / 321 / 1037 | 29 incompatible caption bindings repaired; native keyboard alias corrected; legacy image-file replacements blocked on OpenPLi |
| PiconHub | 21 / 33 / 134 | No Python import or direct-call incompatibility found; 226 existing tests passed |
| GSU | 51 / 49 / 674 | No Python import or direct-call incompatibility found; 411 existing tests passed |

FullHDGlass shared XML initially had 29 incompatible typed bindings. OpenPLi Button/Label components provide fake source methods, so incorrect bindings can show an initial caption but fail to propagate later text changes. Timer/hotkey screens have the reverse mismatch. The scoped adapter changes only FullHDGlass entries in OpenPLi's in-memory skin registry. It clones elements, preserves geometry/artwork and native handlers, and adds native conditional guards for fields that the image does not provide. OpenATV, other skins and /etc/enigma2 user overrides are excluded.

The OpenPLi controller is named VirtualKeyBoard; the old same-named FullHDGlass template lacks prompt, mode, locale and colour/help captions. Only the OpenPLi registry aliases the existing complete VirtualKeyboard template to that controller. Keyboard actions and input handling stay native; the 14x5 grid and 67-pixel row alias remain aligned.

OpenPLi is now included in the existing protection against replacing Menu.py, ChannelSelection.py, ServiceScan.py or encoding.conf. The legacy 2xOK/channel patch option is not offered there. The dormant Menu-new17.py import of getSetupTitle is retained as an explicit inactive legacy exception only while the tested ownership guard remains present.

## Validation

- Eight tests against each real OpenPLi source tree reproduce stale native button captions, exercise repaired native Button/StaticText updates, verify all typed shared bindings, test native conditional processing and keyboard fields, and prohibit legacy image writes.
- Native row/navigation replay: 13 tests; native HD/FHD/WQHD/UHD reference-scale replay: 1 test. The test harness now supplies the actual OpenPLi global skin/desktop imports and native list movement interface; runtime geometry code did not require an OpenPLi fork.
- FullHDGlass existing controller fingerprint/presentation suite: 24 tests passed, plus two new negative guard tests. Configuration-font suite: 14 tests; runtime ownership checks passed. Exact new import nodes and condition expressions are recorded in design/openpli-compatibility; unexpected hook or action edits still fail the frozen fingerprint.
- PiconHub inline audit: 6 literal/imported templates, 58 typed bindings, zero binding errors. GSU: 153 templates, 837 typed bindings, zero binding errors. Their generated/dynamic screens are not all statically resolved; existing generated-layout tests remain required.
- A dedicated read-only GitHub Actions matrix checks OpenPLi release-9.2/develop and runs source regression suites. It neither builds nor publishes packages and has no contents-write permission.

## Remaining receiver checks and release state

No new binary was published and no production feed was changed. The owner accepted the previous OpenATV candidates (FullHDGlass 1.0.62-test2, PiconHub 0.1.39-test2 and GSU 13.41-r1 TEST); this OpenPLi change is separate source work and needs a new FullHDGlass test version before distribution. Never overwrite those immutable accepted IPKs.

Physical OpenPLi installation/dependency resolution, first boot, keyboard, list scrolling, channel selection, timer editing, scan and plugin browser still require receiver validation. CAM execution, C++ ABI, networking, front-panel devices and GLES/WQHD painting are not proven by source tests. Main FullHDGlass output remains FHD. Shared CoolTV/EMC layouts reference CoolNextEvent/CoolPico/EMCServiceTime/EMCMovieInfo/EMCClockToText from their separately installed external plugins; this review does not certify those external builds. Static/dynamic unresolved fields remain recorded in reports instead of being claimed as fully covered.
