# Warder Backup & Restore — development for 0.41.7

Owner approved implementation on 26.11.2026, including local credentials where necessary. This separate draft starts from 0.41.6 candidate `277cc0a4c86e03b8ef5584c0cb6b61e578d6ba1a`; it must not alter PR #19 or current stable production.

First implementation: Warder centre → Backup and restore. Select projects (OK), choose detected local destination (yellow), create verified JSON (green), browse verified backups (blue), explicit restore confirmation. Portable allowlist derived from actual project source. Native Enigma2 config elements are restored only if present and valid on target image; open installed plugins once first. Radio preferences use its state.json, not its URLs, favourites or tokens. Backups contain no complete settings files. Before restoration make a separate portable rollback snapshot; verify native save and Radio state. SHA-256 is integrity, not authenticity or encryption. No internet/upload, no remote mounts, no automatic deletion, no restart without owner action.

Remaining: validate actual FullHDGlass application and cross-image configuration hooks on physical receivers; expand portable PiconHub selectors, radio favourites/custom stations with explicit private-data handling, and safe optional credential export (encrypted local archive; no OAuth transfer by default). Complete UI review and translations; CI, actual restore/rollback and USB compatibility must pass before release. Version is intentionally not bumped on this stacked draft until 0.41.6 is finished. Do not claim full settings coverage or credential support in this first implementation.

## Private backup backend checkpoint

Optional AES-256-GCM with scrypt (N=32768, r=8, p=1), fresh salt/nonce, authenticated format and password minimum 12 characters. No custom crypto fallback, no installation or network. If the receiver lacks cryptography, private backup is unavailable. Explicitly allow only the native YouTube API key and validated Radio favourites/custom lists in encrypted form; no OAuth/session tokens, history, credentials embedded in URL userinfo, or arbitrary settings. Plaintext save validates before writing; encrypted rollback is required for private restore. Actual receiver provider availability, masked password UI and failure/recovery testing remain open. The backend is not yet exposed in GUI; ordinary portable backup is unchanged. Tests include rejection of plaintext, wrong password/tamper, encrypted rollback and preservation of Radio history; crypto tests skip if provider missing.

## Private backup GUI checkpoint

Create mode choice (only when the local crypto provider passes a small self-test), dedicated Warder masked remote keyboard, double password entry for new private backups, locked preview requiring explicit unlock, no displayed secret values, selection/close clears the stored password reference. Private archive preview is authenticated before restore confirmation. Restore rechecks the payload fingerprint to reject a changed file after preview. Encryption and opening private archives use the existing Twisted worker mechanism; native restoration still runs on the GUI thread and must be checked for latency on actual receivers. Eleven new captions in all 21 languages. Receiver crypto provider/full-cost KDF availability, USB filesystem behavior and native restore/rollback require physical validation. Passwords are never saved in configuration or logs by this feature. No OAuth transfer or network. Version/production unchanged.

## Recovery and removable storage checkpoint

Predecessor b530b389fc85b41711fe7e05dd32da30a1a3f49d: four CI families successful. Backup writes use a pinned directory descriptor, hidden exclusive temporary file, fsync/readback, mount identity rechecks, atomic rename and directory fsync; failure before rename cleans only the pinned temporary file. A completed file may remain after a post-rename verification failure, not reported as success. A verified rollback archive is now created under the local receiver backup directory before any settings change, including when the source is USB/HDD. Missing Radio state is accepted only when the local plugin entry exists, with effective Store defaults used for previously absent keys; corrupt/unsupported state is not replaced. Error path reports successful rollback or need for manual recovery, with recovery file location. Tests simulate new Radio state, removable mount loss and native save failure. Full power-loss atomicity across native Enigma2 and Radio files cannot be guaranteed; local rollback file is the recovery route, not automatic boot-time restoration. Real FAT/exFAT and receiver-specific native hooks remain to be tested; separate draft only.
